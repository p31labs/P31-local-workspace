## 2. Install the worker dependencies

**Version-pin fix (root cause, already applied @ `84c4748`):** the worker's
`package.json` originally pinned `x402-hono@^0.5.0` and `@coinbase/x402@^0.4.0`
(copied from the billing worker). Those ranges resolve to **nothing** on the registry —
the real published versions are `x402-hono@1.2.0` and `@coinbase/x402@2.1.0`.
`pnpm install` therefore "succeeds" but **silently skips** the two x402 packages,
so `tsc` then fails with `Cannot find module 'x402-hono'`. The pins are now
`^1.2.0` / `^2.1.0`, and `@cloudflare/workers-types` is bumped to `^5.0.0`
(to match `wrangler@4.x`'s `^5.20260708.1` peer, avoiding an install conflict).

```bash
cd software/workers/mcp-x402-gateway
pnpm install --no-frozen-lockfile
# Verify the x402 deps actually landed (NOT "(missing)"):
pnpm ls x402-hono @coinbase/x402
# If pnpm skips them (workspace lockfile predates this worker), isolate with npm:
npm install --legacy-peer-deps
```

> The agent's own environment could not complete this step: `pnpm` resolves the
> 73-project workspace but omits the worker's x402 deps (pre-dated lockfile),
> and `npm install` hangs on the flaky registry. On a healthy machine with registry
> access, the corrected pins above install cleanly.
