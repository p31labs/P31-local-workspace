# L3.4 — Node MCP Bridge: RUNBOOK

**Status: DONE + local test green (48 tools routed across 4 backends).**

The x402 Worker (L3.2) fronts the 4 hand-rolled MCP servers but cannot spawn
child processes on Workers runtime. This bridge closes that gap: a supervised
Node service that spawns the stdio servers and exposes them over MCP Streamable
HTTP, bound to from the Worker edge.

## Architecture

```
client → x402 Worker (L3.2, /mcp + Payment-Signature) → service binding →
         Node bridge (:8788 /mcp) → 4 supervised stdio MCP servers
              ├─ oasis      (cli/mcp-server.js)         stream   11 tools
              ├─ registry   (cli/component-registry.js) stream    5 tools
              ├─ love       (cli/love-registry.js)      stream    3 tools
              └─ phosforge  (tools/phos-forge/mcp-server.mjs) batch 29 tools
```

- **Fan-out catalog:** `tools/list` returns the unified 48-tool catalog; the
  bridge builds a `{toolName → backendId}` route table.
- **Routing:** `tools/call` is routed by tool name to its owning backend.
- **Supervisor** (`src/stdio-client.mjs`): crashed children restart with
  exponential backoff (max 5) then are marked unhealthy + excluded from routing.
  Streaming backends stay alive; PHOS Forge is spawned fresh per call (batch).
- **Session pinning** is handled by the Worker, not the bridge (bridge is
  stateless at the edge).

## Files

- `bridge/package.json` — ESM, zero runtime deps, `start` / `test` scripts.
- `bridge/src/backends.mjs` — the 4 backend configs + repo-root resolver.
- `bridge/src/stdio-client.mjs` — `StdioBackend` supervisor + JSON-RPC proxy.
- `bridge/src/router.mjs` — `BridgeRouter` (initialize/tools/list/tools/call).
- `bridge/src/index.mjs` — `POST /mcp` + `GET /health` HTTP edge + bootstrap.

## Deploy with the Worker (requires user: secrets + go-ahead)

1. Deploy the bridge as a Workers **Static / Node asset** or a long-lived
   Node service (e.g. Cloudflare Containers / a VM) so the edge Worker can
   reach it over the service binding / a URL.
2. Point the L3.2 Worker at it:
   - service binding `BRIDGE` → this service (preferred), or
   - `BRIDGE_URL` env → `https://<bridge-host>/mcp` and convert the Worker's
     `fetch(BRIDGE, …)` to an external `fetch`.
3. Keep `PRICING` (Worker) and the paid-tool set (`oasis_execute`, `phos-adopt`,
   `jitterbug-run`) in sync — the bridge routes by name; the Worker is the 402
   gate.

> **402→200 end-to-end** is owned by L3.2 (Worker dry-run green). The bridge's
> contract is pure routing: it forwards paid calls to the backends and returns
> their result. Full e2e (unpaid → 402, paid with testnet x402 token → 200)
> exercises the Worker + facilitator and needs the deployed stack.
